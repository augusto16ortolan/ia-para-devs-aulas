# Arquitetura básica do MCP

Para entender MCP, vale pensar em alguns blocos básicos.

## Cliente e servidor

De forma simplificada:

* o **cliente** é quem consome as capacidades;
* o **servidor MCP** é quem expõe essas capacidades de forma organizada.

O cliente pode ser um assistente, um agente, um editor com IA ou outro sistema que queira acessar ferramentas e recursos.

## Tools, resources e prompts

No MCP, alguns conceitos aparecem com frequência:

* **tools:** ações ou operações que podem ser chamadas;
* **resources:** dados, documentos, arquivos ou contextos disponíveis;
* **prompts:** instruções estruturadas que também podem ser oferecidas como parte do sistema.

Esses elementos ajudam a organizar melhor o que está disponível para o cliente.

## Fluxo básico

Em uma visão simples, o fluxo costuma ser:

1. o cliente se conecta ao servidor MCP;
2. o cliente descobre quais capacidades estão disponíveis;
3. o cliente usa tools ou resources conforme a necessidade;
4. o servidor responde de forma padronizada.

## Uma camada de integração

Uma forma útil de pensar no MCP é como uma camada intermediária entre a IA e o mundo externo.

Essa camada não elimina a complexidade do sistema, mas ajuda a organizá-la melhor.
